BEHIND THE STORY

Your words. Playable consequences.

When you send a deal, OpenAI interprets your intention and composes a plan from the game's supported actions. You inspect and accept it, then carry it out.

The game owns evidence, consent rules, possessions and time. When the gate closes, the model sees what actually happened and proposes a new plan without undoing the completed exchange.

Opening dialogue, art, the night-watch event and scene animation are authored. The live proposals are generated. This small host supports copying, delivery, passage, shelter, movement and waiting. It cannot invent new mechanics.

This game uses the reusable Runtime Story SDK. A separate resource-management game uses the same installed package for repairs, power, heat and surveys, including a working Godot client. Developers supply their own mechanics and rules. The tool supplies the shared planning, validation and execution record.

Credits and demonstration limits

Original prototype, story and presentation by Justin with Codex. Scene and character art generated with OpenAI using the project's original concept collection. Original composed procedural score and sound effects. System fonts. No Blender models are used here.

This is a local single-session demonstration. A deterministic planner and an equal-information direct model also passed the three comparison cases. The deterministic planner was faster. Godot execution is verified. Unity and Unreal examples have not been run, and human authoring-time savings have not been measured.
